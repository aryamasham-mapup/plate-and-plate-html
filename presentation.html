01 · Violations

What is a violation?

A violation is a charge mailed to the registered owner by a toll agency, city or police, because a toll was not paid by tag or a traffic, parking or safety rule was broken. Tolls are most of the volume.

Seven stages from file to resolution

Needs review. A person sees the evidence and the reason, corrects or approves it, and the violation re-enters the flow.

StageActivity
Select a violation above to trace it.

Read

A vision model reads the file into a fixed schema with a confidence score. Haiku reads every violation; below 0.80 Sonnet re-reads; still unsure goes to Needs review.

Queue

One Postgres record per violation with a status. Workers claim with SKIP LOCKED; every step is keyed by Violation ID, so a retry never pays twice.

Match

Plate history gives the unit on that local day, then the driver and the toll transaction. Tag reads, registered plates and GPS are stored as evidence.

The first rule that fires is the reason

Rules run in order. The reason decides how the violation is resolved, using the same statuses the Violations tab shows.

What the system does

DisputablePrepares the dispute with proof attached: tag transaction, sale date, GPS trace.
Fleet ResolvablePays, then adds toll + fees to the monthly file for that driver or owner.
Non-actionablePays before the due date, flags the tag, and lists the plate in Register Plates.
ResolvedRecords it so it is never paid twice.
Needs reviewHolds it for a person with the exact reason.
